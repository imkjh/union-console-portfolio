# 개발 과정과 역할

## 문제와 범위

여러 LLM의 답변을 비교할 때 같은 질문을 반복해서 입력하고 창을 오가야 했습니다. 질문 한 번으로 선택한 모델의 결과를 볼 수 있는 개인용 도구를 만들기로 했습니다.

처음에는 실제 연결 가능한 CLI 두 개를 우선 지원하고, 질문 전달부터 답변 비교와 개별 재시도까지 만들기로 했습니다. 대화 이력과 자동 평가는 제외했습니다. 최종적으로 Codex와 Antigravity 두 CLI를 통해 GPT·Gemini·Claude를 연결했습니다.

## 결정 1. 실패한 요청만 다시 실행하기

한 모델이 실패해도 이미 받은 답변까지 다시 요청할 필요는 없습니다. 모델별 상태와 결과를 분리하고, 실패·시간 초과 요청에만 재시도를 허용했습니다.

실행과 재시도에 식별자를 부여해 이전 요청의 늦은 응답이 새 결과를 덮어쓰지 않게 했습니다. 같은 CLI를 사용하는 Gemini·Claude는 차례로 실행하며, GPT는 독립적으로 실행합니다.

## 결정 2. 기존 구독으로 호출하기

개인용 도구에 별도 API 사용료까지 더하고 싶지는 않았습니다. 이미 이용 중인 구독의 공식 CLI를 연결해 기존 사용량 한도 안에서 모델을 호출하는 방식을 선택했습니다. 추가 API 과금 없이 비교 기능을 구현할 수 있다는 점이 판단 근거였습니다. 구독료는 여전히 들며, API 방식과의 비용 차이를 수치로 비교하지는 않았습니다.

대신 CLI 인증과 버전, 실행 환경의 영향을 받아 연결과 검증에 시간이 들었습니다. 조사가 길어졌을 때는 시간 제한을 두고 짧은 실제 호출부터 확인하도록 순서를 조정했습니다. 파일 접근과 명령 실행 차단 검증은 유지했습니다.

## 역할

| 구분 | 맡은 일 |
|---|---|
| 본인 | 문제 정의, MVP 범위·화면 흐름·우선순위 결정, 카드 표시와 재시도 후 기존 답변 유지 확인 |
| Codex | 코드·테스트 작성, 실행 검증, 연동 오류 분석, 시연 촬영·문서 작성 지원 |

## 결과와 한계

개발 환경에서 세 모델의 실제 응답을 한 화면에서 확인했습니다. [35초 영상](media/live-comparison.mp4)은 같은 가상 고객지원 질문에 답하는 GPT·Gemini를 보여줍니다. 실패·시간 초과·재시도는 Demo와 자동 테스트로 확인했습니다.

질문 입력부터 답변 비교와 개별 재시도까지 구현했습니다. 장기 사용이나 시간 절감 효과는 측정하지 않았습니다. 서버 재시작 시 결과가 사라지고, 다른 PC에서 실제 모델을 연결하려면 환경 검증이 필요합니다.
